# Base URL

```text
/api/v1
```

---

# API Response Format

Every API returns the same response format.

Success

```json
{
    "success": true,
    "message": "Operation successful",
    "data": {}
}
```

Error

```json
{
    "success": false,
    "message": "Something went wrong",
    "errors": []
}
```

# API Naming Rules

* Use plural names for resources.
* Use nouns instead of verbs.
* Use HTTP methods correctly.
* Keep endpoint names lowercase.
* Return JSON only.
* Version all APIs using `/api/v1`.

Examples:

```
GET    /api/v1/donors
POST   /api/v1/donors
PUT    /api/v1/donors/{id}
DELETE /api/v1/donors/{id}
```

---

# Final Notes

* All protected APIs require JWT authentication.
* Public APIs include donor registration and login endpoints.
* Every API returns the standard response format.
* Input validation must be performed before processing requests.
* Errors should return meaningful HTTP status codes and messages.

2. Camp
3. Medical Partner

7. Donor Registration

# Notes

* Use RESTful API naming conventions.
* Return JSON responses.
* Use DTOs for request and response objects.
* Never expose database entities directly.
* Validate all incoming requests.
* Secure protected APIs using JWT authentication.
* Handle exceptions using a global exception handler.
