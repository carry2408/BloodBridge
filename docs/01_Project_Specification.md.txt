# 1. Project Overview

## Project Name

**BloodBridge**

## Full Project Title

**BloodBridge – Blood Donation Camp Management System for MSRIT NSS**

## Purpose

BloodBridge is a full-stack web application developed to digitize and streamline the management of blood donation camps conducted by the MSRIT NSS unit.

The system replaces manual paperwork with a centralized digital platform for donor registration, volunteer operations, medical screening, donation tracking, and administrative reporting.

The application is intended to be deployed and used during an actual blood donation camp.

---

# 2. Problem Statement

The current blood donation camp process depends heavily on paper forms and manual coordination.

Common challenges include:

* Manual donor registration
* Time-consuming donor verification
* Difficulty tracking donor progress
* Paper-based medical records
* Manual report preparation
* Slow communication between volunteers
* Increased chances of duplicate entries
* Difficult data retrieval after the event

A centralized digital solution is required to simplify the workflow while remaining easy for volunteers to use.

---

# 3. Project Objective

Develop a production-quality Blood Donation Camp Management System that:

* Simplifies donor registration.
* Reduces paperwork.
* Improves volunteer efficiency.
* Maintains accurate donor records.
* Provides administrators with real-time monitoring.
* Supports approximately 1000–2000 donor registrations.
* Can be fully developed and deployed using free technologies and services.

# 4. Project Scope

## Included in Version 1

* Online donor registration
* Registration confirmation through email
* QR Code generation
* Volunteer team management
* Medical partner management
* Team-based volunteer login
* Donor check-in
* Medical screening management
* Blood donation management
* Administrative dashboard
* Reports and statistics
* Mobile-responsive user interface
* PostgreSQL database
* Free cloud deployment

## Excluded from Version 1

The following features are intentionally excluded to keep Version 1 focused and maintainable.

* SMS notifications
* Certificate generation
* Multiple yearly camps
* Multi-organization support
* AI-based recommendations
* Offline mode
* Volunteer PIN authentication
* Activity logs
* Advanced analytics

These features may be considered for future versions.

# 10. Registration ID Format

Each donor will receive a public Registration ID.

Example:

MSRIT-BDC-2026-0001

Structure:

* MSRIT — Organization
* BDC — Blood Donation Camp
* 2026 — Camp Year
* 0001 — Sequential Registration Number

Internally, the database will maintain numeric primary keys for efficient relationships.

# 14. Project Principles

The following principles govern all design and development decisions.

1. Keep Version 1 simple.
2. Every feature must solve a real operational problem.
3. Avoid unnecessary complexity.
4. Prioritize usability for volunteers.
5. Minimize user interactions.
6. Maintain clean architecture.
7. Follow feature-based organization.
8. Use DTOs for API communication.
9. Build production-quality software.
10. Use only free technologies and deployment platforms whenever possible.

---

The project will be considered successful when:

* Administrators can monitor the camp through dashboards.
* The application supports at least 1000 donor registrations.
* The application is successfully deployed using free cloud services.
